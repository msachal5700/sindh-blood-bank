# Sindh Blood Bank — Deploy Guide

Complete website (frontend + backend in one project): Next.js 15 + Prisma + PostgreSQL.
Already running at https://sindh-blood-bank.vercel.app — this ZIP is the full source of that site,
including the emotional UI redesign and the photorealistic cover (public/cover.jpg).

## What you need (all free)
- A PostgreSQL database URL (Neon.tech free tier works — the live site uses Neon, Singapore region)
- A SESSION_SECRET (any long random string, e.g. generated by `openssl rand -hex 32`)

## Deploy on Vercel
1. Unzip, then push the folder to a GitHub repo (or drag it into Vercel's "Import" flow via Git).
2. In Vercel: Add New → Project → import the repo. Framework auto-detects as Next.js. Don't deploy yet.
3. Project → Settings → Environment Variables — add:
   - `DATABASE_URL` = your Postgres connection string
   - `SESSION_SECRET` = your random secret
   (Or attach a Neon database from the project's Storage tab — that sets DATABASE_URL for you.)
4. From your own computer, inside the unzipped folder, create the tables and load the data:
   ```
   npm install
   DATABASE_URL="<your connection string>" npx prisma db push
   DATABASE_URL="<your connection string>" npm run seed
   ```
   The seed creates 8 cities, 12 branches, 96 stock rows, 14 requests, 12 donations and
   14 test accounts, and writes the generated test-account passwords into
   `TEST_ACCOUNTS.local.md` in the folder you ran it from.
5. Deploy (or redeploy) in Vercel. Done — the site is live.

## Run locally
```
npm install
# .env file with: DATABASE_URL="file:./dev.db" won't work for Postgres schema;
# for a quick local run use the SQLite schema:
DATABASE_URL="file:./dev.db" npx prisma db push --schema prisma/schema.sqlite.prisma
npm run dev
```

## Test accounts
See `TEST_ACCOUNTS.local.md` (the passwords for the currently live site are in this ZIP's copy;
if you re-seed your own database, the seed writes a fresh set with new random passwords).

## Notes
- `app/api/admin/seed/route.ts` is a permanently disabled leftover (returns 404) — safe to delete.
- Never commit `.env` files or `TEST_ACCOUNTS.local.md` to a public repo.
